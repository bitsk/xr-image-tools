# A081 Alpha distribution layout

The installation consists of a writable 24 GiB ext4 image in an existing ext4 GPT partition named `osstore`, and an A081 Android-format recovery image in the active Android slot’s recovery partition (`recovery_a` or `recovery_b`). The boot script resolves the partition by name. A shutdown initramfs moves the backing mount out of the old root by its block device number, unmounts the inner root, detaches the loop and unmounts osstore before poweroff or reboot. The end-user instructions are in [the installation guide](https://github.com/bitsk/openkylin-xr-docs/blob/main/wiki/mix-spatial-alpha.md).

Build in a disposable ARM64 root extracted with numeric ownership, hard links and xattrs from the desktop ISO pinned in `../source.lock.json`. Stage the release packages exported by the component builder for the vr-hands, cinema and saberv profiles. Use the package receipts and compiler-header audits for the selected source commits. Keep the matching system Mesa, kbd, v4l-utils and ARM64 Vulkan loader installed.

Before APT installs the packages, set dpkg a path exclusion for `/usr/share/rvvr-saberv/songs/TheFatRat_Timelapse*` only. Install the complete locked `xr-monado-steamvr-driver` package including its pose observer. Disable the live ISO's OSTree/GRUB kernel postinstall/postremove hooks for the writable root (dpkg statoverrides preserve that choice across package upgrades). Keep the A081 module package and verify that `dpkg --audit` is empty and `apt-get check` succeeds.

Keep the adjacent account helper, calibration helper, SEE drop-in and configuration generator alongside the recipe scripts. Run `prepare-session`, then `configure-root`, inside the disposable root with `MIX_IMAGE_BUILD=1`. These scripts create a model-wide XR profile and desktop account and strip installation-only state. The USB serial login uses the password chosen at installation. The account and calibration units consume only the files provisioned on that device.

Run `import-runtime UPSTREAM_ROOTFS_TAR_ZST STAGED_ROOT` from an isolated root-capable builder. It verifies the source archive before importing the matching native SteamVR and Gamescope pair, private ABI dependencies, and license notices. Then run `enable-xr` with its adjacent unit files, launcher and settings inside the staged root with `MIX_IMAGE_BUILD=1`. The default systemd target starts an unlimited XR session after local calibration and hardware readiness. Distribution of the bundled runtime and observer requires appropriate rights from their holders.

Run `make-root-image SEALED_ARM64_ROOT NEW_IMAGE` as root in an isolated build environment. Use e2fsprogs with extended attribute support. Put the raw image and its recovery into the same payload directory. The raw ext4 file must remain unchanged after generating the release checksums.

Build the ramdisk with `ramdisk.py --help`. Use the locked vendor firmware cache and the kernel's `gen_init_cpio`. Package it with the matching kernel Image, source DTB and the A081 transport template using `xr-kernel/packaging/build-recovery.py`. Verify the packer's readback receipt and publish the full partition-sized recovery.

Name the payload directory `openKylin-3.0-Spatial-Alpha-MIX`. Run `pack-release PAYLOAD_DIRECTORY OUTPUT_DIRECTORY`. The XZ-compressed GNU sparse tar contains exactly two files at its root, the main image and the recovery image. Publish the archive digest, the image checksum list (`SHA256SUMS`), the installer, both Chinese guides, `PACKAGES.tsv` and `release-manifest.json` alongside the archive. Extract it into an empty directory and verify both images with the external checksum list. Keep per-device calibration and Android backups private.

For the R2 maintenance release, use the verified sealed Alpha root as the base and apply the published four-package update in a disposable copy. Place the matching xr-head-tracking, xr-head-tracking-tools, xr-session-manager and xr-diagnostic-tools debs in `packages/` next to `apply-alpha-update`, the first-boot helpers, XR service, SEE drop-in and tracker configuration generator. Generate `payload.sha256` for these inputs and run `apply-alpha-update` as root inside the copy. It refreshes both the dpkg installation and the active tracking capsule. Repack and verify the revised root and recovery, then run `pack-release PAYLOAD_DIRECTORY OUTPUT_DIRECTORY r2`.

Use `pack-repair.py --packages LOCKED_DEB_DIRECTORY --old-recovery ORIGINAL_IMG --new-recovery REVISED_IMG --output COMPANION_INPUT` to export the public repair files. The matching companion for each image release contains that release's download checksums and the same first-boot update tar, unit and repair manifest. The repair manifest identifies the two compatible recovery releases and the delivered update files. Installed headsets stage the update from rooted Android using `install-mix.py repair`, then apply it via systemd on their next openKylin boot. Updating the USB recovery is a separate `update-recovery` operation using the original same-device, same-slot backup. The system image checksum applies to the downloaded bytes and the initial installation transfer. Users can update their writable installed filesystem without matching the pristine image.
